# rl 目录说明

强化学习核心，可脱离 Web 独立运行。本文说明目录结构，并记录各算法在本项目 9×9 五子棋上的实现方式、实验结果与阶段性结论。

## 目录结构

```text
rl/
├── environment/   9×9 五子棋环境（gomoku.py）
├── agents/        AI 实现：BaseAgent / Random / Greedy / PureMCTS / QLearning / DQN / AlphaZero + registry
├── training/      训练脚本：train.py（通用循环）、train_dqn.py、train_alphazero.py
├── evaluation/    胜率评估（evaluate.py）
├── models/        训练产物：权重、检查点、累计局数元数据
└── demo_qlearning.py   Q-Learning 训练/评估演示
```

## 实验设置

- **任务**：9×9 棋盘、五连获胜；棋盘填满且无人成五判和。
- **对照基准**：`random`（随机落子）与 `greedy`（手工贪心启发式）。
- **评测口径**：胜率取自各算法训练脚本的内置评估或专项评估脚本。黑方先行、先手占优，故胜率与执子颜色强相关，判读时需区分执黑 / 执白。
- **训练环境**：Python 3.11 + GPU（RTX 3060，torch 2.14.1+cu132）。

| 算法 | 状态表示 | vs random | vs greedy | 训练规模 | 下一步方向 |
| --- | --- | --- | --- | --- | --- |
| RandomAgent | — | — | — | — | 下限基准，无需改进 |
| GreedyAgent | 13 个手工特征 | — | — | — | 作为当前目标对手 |
| QLearningAgent | 13 个手工特征（线性） | 1.00 | 0.00 | 不足 1 小时 | 除非更换特征表示，暂不继续投入 |
| DQNAgent | 3 通道 CNN | 1.00 | 0.00 | 自对弈约 3 万局，1–2 小时 | 补全状态表示；引入历史对手池 |

## 各算法说明

### RandomAgent —— 随机基准

随机选择合法落子。任何具备基本攻防能力的策略均可稳定取胜，因此各学习型算法的 vs random 最终均达到约 1.00。它仅作为下限基准。

### GreedyAgent —— 贪心启发式基准（当前最强对手）

以 13 个手工特征（成五 / 活四 / 冲四 / 活三 / 眠三 / 活二，以及对手的对应威胁）加权打分选择落子，兼具进攻与防守能力。

**定位**：它是**线性特征表达能力的上限**——本质上是「人工调参得到的线性策略」，即该特征空间内的较优解。

### QLearningAgent —— 线性 Q-Learning

线性函数近似 Q-Learning：`Q(s,a) = w·φ(s,a)`，与 greedy 使用**同一套 13 个手工特征**，区别仅在于权重由学习获得还是人工设定。

| 对手 | 胜率 |
| --- | --- |
| vs random | 1.00 |
| vs greedy | 0.00 |

**训练规模**：不足 1 小时。

**结论**：线性特征结合学习，**上限约等于 greedy**（greedy 本身即该特征空间的手调较优解）；除非更换特征表示，继续投入的意义有限。这印证了一个一般性判断：**要超越手工特征，必须让模型自行学习特征（神经网络），而不仅是学习同一套特征的权重。**

### DQNAgent —— 深度 Q 网络

3 通道 CNN（己方 / 对手 / 空位）输出 81 维 Q 值；采用自对弈（negamax 目标）+ 经验回放 + 目标网络。

| 对手 | 胜率 |
| --- | --- |
| vs random | 1.00 |
| vs greedy | 0.00 |

**训练规模**：自对弈约 3 万局，约 1–2 小时。

**结论**：表现不及预期，vs greedy 始终为 0。已尝试的改进均未见效——直接对 greedy 训练会因长期拿不到胜局而**塌缩**（vs random 一并退化）；课程混合（random 逐步过渡到 greedy）与奖励塑形也未能带来提升。

初步判断瓶颈可能有两处，**尚待验证**：

1. **状态表示**：3 通道缺少「对手上一步」与「当前执子方」信息；这两项在 AlphaZero 上验证有效，对同属神经网络策略的 DQN 应同样适用；
2. **对手多样性**：纯自对弈容易在同一水平上循环退化，可引入历史对手池。**该判断已在 AlphaZero 上得到印证**——其纯自对弈在 3500 局时坍塌为固定 9 手线路（详见下文 AlphaZero 一节），现已改用混合对手应对。

### AlphaZeroAgent —— AlphaZero-lite（当前主线，训练中）

**方法**：MCTS（PUCT）结合双头（策略 / 价值）网络。已落地：4 通道输入（己方 / 对手 / 对手上一步 / 是否先手）、8× 数据增强（旋转 / 镜像）、Dirichlet 根噪声、L2 正则、按策略 KL 散度自适应调节学习率、400 次模拟/步、**混合对手（纯自对弈 + 对战 greedy）**、断点续训与无限训练。

**训练历程**

| 阶段 | 关键改动 | 现象与结论 |
| --- | --- | --- |
| 一 | 3 通道输入、100 次模拟 | 学会棋子聚集并主动向对手靠拢，但未掌握防守（对手成线时不在线上阻拦）；约 4000 局后指标不再增长 |
| 二 | 模拟次数 100 → 800 | 仍无改善。此时 value loss 已接近 0、policy loss 停滞在 2.04——说明价值网络已收敛，**瓶颈不在价值学习本身**，单独提高模拟次数不足以突破 |
| 三 | 对照公开实现（junxiaosong/AlphaZero_Gomoku）后改进：4 通道输入、L2 正则、KL 自适应学习率；模拟次数回调至 400 以加快迭代 | 训练指标转为健康：policy loss 4.03 → 3.46，value loss 1.18 → 0.44，KL 收敛至目标值 0.02，学习率在 4.0e-4 – 1.3e-3 间自适应调节 |
| 四 | 沿用纯自对弈继续训练至 3500 局 | 出现**自对弈坍塌**：自对弈均长一路缩短至 9.2 手（10 局中 9 局恰为 9 手），对 greedy 执黑胜率由 0.25 回落至 0.15。诊断与应对见下节 |
| 五 | 使用混合对手训练至4200局 | 自对弈坍塌解除（手数回到 9–35 的宽分布）；对 greedy **执黑 0.15 → 0.55、执白 0.00 → 0.10**，为迄今最大跃升。详见阶段五一节 |
| 六 | 继续训练至 5560 局；补入搜索树跨步复用、纯 MCTS 基线、best/current 存档，并把对战贪心局改为仅开局抽样 | 对 greedy 整体停在 **0.42–0.48** 不再上移（执黑 0.75 → 0.50、执白 0.20 → 0.35，黑白趋于均衡，差异均在样本噪声内），**进入平台期**。详见阶段六一节 |

**阶段四：自对弈坍塌的诊断与应对（3500 局）**

自对弈平均手数一路缩短：14.4 → 12.4 → 10.6 → **9.2**，且 10 局中有 9 局精确为 9 手。9 手正是五子棋的最快取胜——黑方（先手）用第 5 颗子成五，白方全程未作阻拦。与此同时，对 greedy 执黑胜率由 0.25 回落到 0.15。

**推论**：网络策略偏进攻、防守薄弱；而纯自对弈中双方是同一个网络，白方同样只顾进攻，于是黑方总能 9 手速胜。这构成恶性循环——回放池被同一条线路填满，防守能力永远得不到训练，网络愈发只会这一条线。这也解释了主观体验上的「棋力回落」：模型对自身固定线路过拟合，一旦被正常防守便失去章法。

**措施（方案 A：混合对手）**：每局以 **50%** 概率改为对战 greedy（随机执黑 / 执白，且只记录网络自己的落子）。greedy 会防守，能制造纯自对弈中不会出现的「必须阻挡」局面，从而为网络补上防守训练信号。（阶段五中该比例提高到 0.6。）

**配套监测**：日志每 10 局输出自对弈各局手数、均长与**短局占比**（≤11 手；坍塌时接近 100%），以及对 greedy 的累计胜率。前者判断坍塌是否复发，后者作为进度指标。

**各阶段结果**（各 20 局；vs random 始终为 1.00）

| 累计局数 | vs greedy 执黑 | vs greedy 执白 | 自对弈均长 |
| --- | --- | --- | --- |
| 2530 | 0.20 | 0.00 | 14.4 |
| 2880 | 0.25 | 0.00 | 12.4 |
| 3500 | 0.15 | 0.00 | 9.2（坍塌）|
| **4200** | **0.55** | **0.10** | 9–35（宽分布）|

**阶段五：混合对手见效；漏堵问题定位为搜索深度不足（4200 局）**

改为混合对手（0.6 greedy）后，自对弈坍塌解除（手数回到 9–35 的宽分布），对 greedy 的胜率出现迄今最大跃升：**执黑 0.15 → 0.55，执白首次取得 0.10**。

但前端实测发现一个缺陷：**对手成「活三」时模型偶尔不堵，转而去做自己的活三**。定位过程如下：

1. 先构造 5 个「必须堵」的简单局面（行 / 列 / 斜向，含己方也能成活三的情形）——在确定性 argmax 下**全部正确堵住**，说明模型并非不具备防守概念；
2. 用前端提供的真实局面复现（23 子，黑方 (4,2)(5,3)(6,4) 成活三，轮白方）：模型确实走了自己做活三那手，**且与温度抽样无关**（23 子远超开局窗口，属纯 argmax 决策）；
3. 查看该局面的访问次数分布：第一名仅占 **24.3%**，两个正确堵点只排第 4（6.5%）与第 6（5.5%）——**分布平坦，说明 400 次模拟在复杂局面下未把战术搜透**；
4. 只改变模拟次数做对照：

| 模拟次数 | 选择 | 结果 | 前三名占比 |
| --- | --- | --- | --- |
| 400 | 自己做三 | 未堵 ✗ | 24% / 15% / 13% |
| 800 | 自己做三 | 未堵 ✗ | 15% / 10% / 8% |
| 1600 | **堵点** | **堵住 ✓** | 47% / 8% / 5% |
| 3200 | **堵点** | **堵住 ✓** | 73% / 4% / 2% |

**结论：该实例属搜索深度不足，而非「不会防守」**——正确手一直在候选之中，只是需要更深的搜索才能把它顶上来。这也解释了早期「模拟次数提到 800 仍无改善」：当时网络还是 3 通道的弱版本，深度不足以补偿。

**同期的一处独立修正（抽样候选筛选）**：排查过程中发现，开启开局温度抽样时，那些**只被访问过 1 次、等于没搜过**的走法也会被抽中（正确堵点占 80%–99% 的访问次数，「做自己活三」仅占 0.3%）。已将抽样候选限制为**访问次数达到最高次数 10% 以上**的走法；相关构造局面的堵截率由 12–14/15 提升到 **15/15**，同时空盘开局仍保留多种走法。此项与上述搜索深度问题相互独立。

**阶段六：进入平台期，转向工程改进（5560 局）**

4200 → 5560 局，对 greedy 的整体水平停在 **0.42–0.48** 不再上移（执黑 0.75 → 0.50、执白 0.20 → 0.35，一降一升、黑白趋于均衡；20 局样本下这些差异都在噪声范围内）。自对弈均长稳定在 14–15 手、短局 2–4/10，**未再出现坍塌**。

据此判断：**继续堆局数的边际收益已经很小**，瓶颈回到前面已定位的两处——搜索被摊薄（每步约 50 个候选摊薄 400 次模拟），以及对战贪心局每一步都在抽样、数据质量被自我拉低。围绕这两处，完成了三项工程改进与一项训练数据修正：

1. **搜索树跨步复用**：保留上一步的子树、以其子节点为新根，省去重复搜索（自对弈、对战、评估、前端全部受益）。复用会让已展开的子节点跳过 `_expand`，从而加不上根节点的 Dirichlet 噪声——为保证自对弈探索不退化，额外保存了未加噪先验 `P_raw`，复用时从未加噪版本重新混合噪声。
2. **纯 MCTS 基线**（`rl/agents/mcts_pure.py`）：UCT + 随机模拟、不使用神经网络估值，用于回答「神经网络相对纯搜索带来多少增益」；已注册为可选 AI `mcts_pure`。实测结果出人意料但很有说明性——**纯 MCTS 对 greedy 0/10、0/10 全败，而 AlphaZero 对纯 MCTS 10/10、10/10 全胜**：即「只有树搜索、没有估值网络」在 9×9 上几乎不起作用（随机模拟很难走成五连，搜索得到的状态价值近似无效）。这从反面支持了引入价值网络与策略网络的必要性。**局限**：正因如此，它不能充当「网络带来多少增益」的强度标尺；若需要更强的搜索基线，应把随机模拟换成轻量启发式走子。
3. **best / current 双模型存档**：只在对 greedy 胜率创新高时才更新 `models/alphazero_best.pt`，避免低谷期权重覆盖历史最佳；最佳成绩记入 `alphazero_meta.json` 的 `best_greedy` 字段，跨重启保留。
4. **对战贪心局改为仅开局抽样**：此前这类对局每一步都按温度抽样，于是「只被访问过一两次、等于没搜过」的走法也会被选中，既拉低对局质量、又让日志里的胜率严重失真（这正是它长期显示 0.2x 而独立评估为 0.5x 的原因之一）。现在只在前 6 手内抽样、之后一律走访问次数最多的手，抽样候选也限定为「访问次数 ≥ 最高次数 10%」。抽样逻辑抽成了 `alphazero.sample_action`，由实战 Agent 与训练共用，避免两处语义漂移。

**待办优化清单**（按优先级排序，供协作者选用）

- **A：只搜索已有棋子附近的候选点**（最划算）。五子棋常识：远离棋子的点几乎不可能好。候选由约 50 压到 15–20 个，等效于**不花额外时间把有效搜索深度提升约 3 倍**，训练与对战同时受益。
- **B：提高模拟次数** 400 → 1600。实验已证可解决复杂局面的漏堵，但训练与对战都慢 2–4 倍，前端每步约 4–8 秒。
- **C：引入历史对手池**，或让高模拟次数的自己当陪练，增加局面多样性，避免只适应 greedy。
- **D：评估对手自动升级**。模型明显超过当前基准后，逐步提高对手强度（例如把基准的模拟次数由 1000 递增到 5000），避免基准失去区分度。
- **E：记录 explained variance**（价值网络预测值与真实胜负的相关程度），比只看 value loss 更能回答「价值网络是否真的有用」。
- **F：扩大网络容量**（暂不建议）。现有网络为 3 层 × 64 通道、约 **9.5 万**参数；已直接读取参考实现的权重核对，其为 32 / 64 / 128 通道、约 **11.9 万**参数——**容量相当，说明容量不是当前瓶颈**。若仍要尝试，需注意：改容量后**无法直接 `load_state_dict` 续训**，只能从头训练，或做「部分权重迁移」的暖启动（形状匹配的部分拷贝过去、新增部分随机初始化、优化器状态需重置）。
- **G：继续训练**，观察是否还能自然增长。

**预期学习阶段**

```text
0 随机 → 1 聚集 → 2 防守 → 3 做活三/活四 → 4 双杀 → 5 战胜 greedy
```

**参考对照**：公开实现（8×8 五连）约需 2000–3000 局、800 次模拟/步达到可用水平。9×9 状态空间更大，预计需 **5000–10000 局才能稳定具备「堵截与做威胁」能力**，战胜 greedy 需要更久。

## 训练与复现

- 棋盘 9×9、五连。
- 训练环境：Python 3.11 + GPU（RTX 3060，torch 2.14.1+cu132）。
- AlphaZero 训练入口：项目根目录双击 [训练AlphaZero.bat](../训练AlphaZero.bat)，或执行 `py -3.11 -m rl.training.train_alphazero`（无限训练：40% 纯自对弈 + 60% 对战 greedy；每 10 局存盘并输出自对弈各局手数、短局占比与对 greedy 累计胜率；每 1000 局评估；Ctrl+C 停止后再次运行自动续训）。
- DQN 训练入口：`py -3.11 -m rl.training.train_dqn`（同样支持无限训练与断点续训）。
- 模型产物：`models/alphazero.pt`（当前检查点）、`models/alphazero_best.pt`（历史最佳，只在对 greedy 胜率创新高时更新）、`models/alphazero_meta.json`（累计局数与历史最佳成绩）、`models/dqn.pt` 与 `models/dqn_meta.json`、`models/q_learning.json`；`models/old_alphazero.*`（累计 17700 局）为改进前的历史版本，仅作留档。
