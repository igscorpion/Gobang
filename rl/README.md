# rl 目录说明

强化学习核心，可脱离 Web 独立运行。本文说明目录结构，并记录各算法在本项目 9×9 五子棋上的实现方式、实验结果与结论。

## 目录结构

```text
rl/
├── environment/   9×9 五子棋环境（gomoku.py）
├── agents/        AI 实现：BaseAgent / Random / Greedy / Minimax / PureMCTS / QLearning / DQN / AlphaZero + registry
├── training/      训练脚本：train.py（通用循环）、train_dqn.py、train_alphazero.py
├── evaluation/    评估：evaluate.py（通用框架）、eval_alphazero.py、eval_minimax.py（专项评估）
├── models/        训练产物：权重、检查点、累计局数元数据
└── demo_qlearning.py   Q-Learning 训练/评估演示
```

## 实验设置

- **任务**：9×9 棋盘、五连获胜；棋盘填满且无人成五判和。
- **对照基准**：`random`（随机落子）与 `greedy`（手工贪心启发式）；另有 `mcts_pure`（纯树搜索，已证实不适合充当强度标尺，见「纯 MCTS 基准」）。
- **评测口径**：黑方先行、先手优势明显，故胜率与执子颜色强相关，AlphaZero 一律**分执黑 / 执白**报告；结果按**胜 / 和 / 负**三项分别统计，不合并为单一「非胜」——五子棋中和棋对先手是坏结果、对后手是好结果，合并会掩盖真实差异。
- **评测噪声**：见「评估噪声」。**10–20 局、0.1 量级的差异不足以判定优劣**，对照实验需要更多局数或多次重复。
- **训练环境**：Python 3.11 + GPU（RTX 3060，torch 2.14.1+cu132）；Web 端另有 CPU 环境。

## 各算法说明

### RandomAgent —— 随机基准

随机选择合法落子。任何具备基本攻防能力的策略均可稳定取胜，因此各学习型算法的 vs random 最终均达到约 1.00。仅作下限基准。

### GreedyAgent —— 贪心启发式基准（当前目标对手）

以 13 个手工特征（成五 / 活四 / 冲四 / 活三 / 眠三 / 活二，以及对手的对应威胁）加权打分选择落子，兼具进攻与防守。

**定位**：它是**线性特征表达能力的上限**——本质是「人工调参得到的线性策略」，即该特征空间内的较优解。

### MinimaxAgent —— Negamax + Alpha-Beta（新增对照，评测待完成）

实现位于 `rl/agents/minimax_agent.py`。采用 Negamax 递归模拟双方轮流落子，叶节点用与 Greedy 相同的 13 维棋型特征估值；终局使用远高于普通棋型分值的胜负分，并按搜索层数微调，以偏好尽快获胜、延迟失败。Alpha-Beta 在当前最好分数已不可能被改善时跳过分支；对**相同候选动作集合和估值函数**，它与未剪枝 Minimax 的理论搜索结果一致。

它与已有搜索算法的区别：Greedy 只比较当前一步的手工棋型分数；Minimax 会递归考虑对手的最优回应；Pure MCTS 用随机模拟与 UCT，AlphaZero 用策略/价值网络引导 PUCT，二者都不等价于 Minimax。

为控制 9×9 棋盘的分支因子，普通候选仅取已有棋子邻域内、按 Greedy 棋型分排序的前若干手；直接成五以及堵住对手下一手成五的动作会全数保留，不受候选上限影响。这种候选筛选是启发式剪枝，**可能遗漏远处落点或更长组合威胁，因此搜索不是完整的全动作空间 Minimax**。默认深度 2、候选上限 8、邻域半径 2；更深或增大候选数会显著增加耗时。新增评估结果尚未跑出，不应据此声称强于 Greedy / AlphaZero。

### QLearningAgent —— 线性 Q-Learning

线性函数近似：`Q(s,a) = w·φ(s,a)`，与 greedy 使用**同一套 13 个手工特征**，区别仅在权重由学习获得还是人工设定。vs random 1.00、vs greedy 0.00，训练规模不足 1 小时。

**结论**：线性特征结合学习，**上限约等于 greedy**；除非更换特征表示，继续投入意义有限。这印证了一个一般性判断：**要超越手工特征，必须让模型自行学习特征，而不仅是学习同一套特征的权重。**

### DQNAgent —— 深度 Q 网络

3 通道 CNN（己方 / 对手 / 空位）输出 81 维 Q 值；自对弈（negamax 目标）+ 经验回放 + 目标网络。vs random 1.00、vs greedy 0.00，自对弈约 3 万局、1–2 小时。

**结论**：vs greedy 始终为 0，未达到可用水平。直接对 greedy 训练会因长期无法取得胜局而**塌缩**（vs random 一并退化）；课程混合与奖励塑形也未见效。瓶颈判断**尚待验证**：

1. **状态表示**：3 通道缺少「对手上一步」与「当前执子方」，这两项在 AlphaZero 上已验证有效；
2. **对手多样性**：纯自对弈容易在同一水平循环退化，可引入历史对手池——**该判断已在 AlphaZero 上得到印证**（其纯自对弈在 3500 局时坍塌为固定 9 手线路）。

### AlphaZeroAgent —— AlphaZero-lite（当前主线）

**方法**

- **网络**：输入 4 通道（己方 / 对手 / 对手上一步 / 是否先手）；3 层 3×3 卷积（各 64 通道）；策略头 1×1 卷积(2) + 全连接输出 81 维 logits；价值头 1×1 卷积(1) + 全连接(64) + 输出 tanh 标量。共 **94,935** 参数。
- **训练配置**：40% 纯自对弈 + **60% 对战 greedy**；每步 400 次模拟、c_puct 1.4；Dirichlet 根噪声 ε=0.25、α=0.3；8× 数据增强（旋转 / 镜像）；batch 512，同一 minibatch 最多 5 轮；L2 1e-4；按策略 KL 散度自适应调节学习率（目标 0.02），并按累计局数每 2000 局将基础学习率减半。
- **搜索**：PUCT；**跨步复用搜索树**（保留上一步子树，以对手落子对应的子节点为新根）。
- **落子策略**：开局前 6 手按温度抽样，之后取访问次数最多的一手；抽样候选限定为访问次数 ≥ 最高次数 10% 的走法，避免选中「只被访问过一两次、相当于未被搜索」的点。实战与训练共用 `alphazero.sample_action`，避免两处语义漂移。
- **保存策略**：每 10 局存盘，存**权重指数滑动平均（EMA，衰减 0.999）**而非原始权重——训练后期权重在好点附近摆动，平均值更稳；同时维护 `alphazero_best.pt`，只在对 greedy 胜率创新高时更新；评估按**累计局数**每 1000 局触发。

**训练历程**

| 阶段 | 关键改动 | 现象与结论 |
| --- | --- | --- |
| 一 | 3 通道输入、100 次模拟 | 学会棋子聚集并主动向对手靠拢，但未掌握防守；约 4000 局后指标不再增长 |
| 二 | 模拟次数 100 → 800 | 仍无改善。value loss 已接近 0、policy loss 停滞在 2.04，说明价值网络已收敛，**瓶颈不在价值学习本身** |
| 三 | 对照公开实现后改进：4 通道输入、L2 正则、KL 自适应学习率；模拟次数回调至 400 | 训练指标转为健康：policy loss 4.03 → 3.46，value loss 1.18 → 0.44，学习率在 4.0e-4 – 1.3e-3 间自适应 |
| 四 | 沿用纯自对弈训练至 3500 局 | 出现**自对弈坍塌**：自对弈均长缩短至 9.2 手（10 局中 9 局恰为 9 手），对 greedy 执黑由 0.25 回落至 0.15 |
| 五 | 混合对手，训练至 4200 局 | 坍塌解除（手数回到 9–35 的宽分布）；对 greedy **执黑 0.15 → 0.55、执白 0.00 → 0.10**（各 20 局）|
| 六 | 训练至 5560 局，补入搜索树复用、纯 MCTS 基线、best 存档、对战贪心局仅开局抽样 | 对 greedy 停在 **0.42–0.48**（各 20 局），判定进入平台期 |
| 七 | 沿用上述改动训练至 6470 局 | 对 greedy 平均升至 **0.75**（执黑 0.85 / 执白 0.65，各 20 局），自对弈均长 22.9 手、短局 0/10。**样本量有限，宜作方向性判断** |

**关键实验记录**

**1. 自对弈坍塌与混合对手（3500 → 4200 局）**

- **现象**：自对弈平均手数一路缩短 14.4 → 12.4 → 10.6 → **9.2**，且 10 局中 9 局精确为 9 手——正是五子棋最快取胜（黑方第 5 子成五、白方全程未阻拦）；对 greedy 执黑由 0.25 回落至 0.15。
- **推论**：网络偏进攻、防守薄弱，而纯自对弈双方是同一网络，白方同样只顾进攻，于是黑方总能速胜。回放池被同一条线路填满，防守能力得不到训练，构成恶性循环。
- **措施**：每局以一定概率改为对战 greedy（随机执黑 / 执白，只记录网络自己的落子）；比例先 0.5、后提高到 0.6。greedy 会防守，能制造纯自对弈中不会出现的「必须阻挡」局面。
- **结果**：坍塌解除，执黑 0.15 → 0.55、执白首次取得 0.10（各 20 局）。配套监测：日志每 10 局输出自对弈各局手数、均长、短局占比（≤11 手）与对 greedy 累计胜率。

**2. 漏堵问题的定位（4200 局）**

- **现象**：前端实测发现，对手成「活三」时模型偶尔不堵，转而去做自己的活三。
- **定位**：先在 5 个「必须堵」的简单局面（行 / 列 / 斜向，含己方也能成活三的情形）验证——确定性 argmax 下**全部正确堵住**；再用前端提供的真实局面复现（23 子，黑方 (4,2)(5,3)(6,4) 成活三，轮白方）：模型确实选择了自己做活三的那一手，且**与温度抽样无关**（23 子远超开局窗口，属纯 argmax 决策）。该局面的访问次数分布显示第一名仅占 **24.3%**，两个正确堵点只排第 4（6.5%）与第 6（5.5%），分布相当平坦。
- **模拟次数对照**（注意：**单个构造局面**）：

| 模拟次数 | 选择 | 结果 | 前三名占比 |
| --- | --- | --- | --- |
| 400 | 自己做三 | 未堵 ✗ | 24% / 15% / 13% |
| 800 | 自己做三 | 未堵 ✗ | 15% / 10% / 8% |
| 1600 | **堵点** | **堵住 ✓** | 47% / 8% / 5% |
| 3200 | **堵点** | **堵住 ✓** | 73% / 4% / 2% |

- **整体对照**：同一冻结权重、每色 10 局，400 次模拟两色平均胜 0.55，1600 次为 0.80。方向与上面的构造局面一致，**但样本偏小**（同一条件下的重复测量波动可达 0.4，见「评估噪声」）。该结果支持「增加模拟次数可提升实战水平」这一判断；受样本量限制，尚不足以确认模拟次数是当前的主要瓶颈。
- **同期独立修正（抽样候选筛选）**：开启开局温度抽样时，「只被访问过 1 次、相当于未被搜索」的走法也会被选中（正确堵点占 80%–99% 的访问次数，「做自己活三」仅占 0.3%）。已将抽样候选限制为访问次数 ≥ 最高次数 10% 的走法，构造局面堵截率由 12–14/15 提升到 **15/15**，同时空盘开局仍保留多种走法。

**3. 工程与训练机制改进（5560 → 6650 局）**

围绕两个疑点——搜索被摊薄、以及对战贪心局全程抽样导致数据质量偏低——完成以下改动：

| 改动 | 内容与理由 |
| --- | --- |
| 搜索树跨步复用 | 保留上一步子树、以对手落子对应的子节点为新根，省去重复搜索。复用会让已展开子节点跳过 `_expand`、无法为根节点添加 Dirichlet 噪声，因此额外保存未加噪先验 `P_raw`，复用时重新混噪 |
| 权重 EMA | 训练仍用原始权重，评估 / 存盘 / best 存档一律用衰减 0.999 的滑动平均，抑制训练后期的权重震荡 |
| 学习率衰减 | 基础学习率每累计 2000 局减半（约 6800 局时降为初始值的 1/8），KL 自适应仍在其之上调节 |
| best / current 双存档 | 只在对 greedy 胜率创新高时更新 `alphazero_best.pt`，避免低谷期权重覆盖历史最佳 |
| 评估触发条件修正 | 原为「本次运行局数 % 1000」，训练频繁重启导致评估与 best 存档始终不触发（`best_greedy` 长期为 −1.0）；改为按累计局数触发 |
| 评估分胜 / 和 / 负 | 原口径把和棋与败局合并为「非胜」，会掩盖「打平」与「输掉」的区别 |
| 对战贪心局仅开局抽样 | 原为每一步都抽样，使「只被访问过一两次」的走法也会被选中，既降低对局质量、又让日志胜率严重失真（日志长期 0.2x 而独立评估 0.5x）。现只在前 6 手抽样 |

**效果**：6470 局对 greedy 平均升至 0.75（各 20 局），自对弈均长 22.9 手、短局 0/10，为当时最好水平。

**4. 纯 MCTS 基准：负面结论**

为回答「神经网络相对纯搜索带来多少增益」，实现了不依赖训练产物的纯 MCTS（UCT + 随机模拟 + 反向传播，`rl/agents/mcts_pure.py`，已注册为 `mcts_pure`）。

| 对局（每色 10 局）| 结果 |
| --- | --- |
| 纯 MCTS(1000) vs greedy | 0/10、0/10 全败 |
| AlphaZero vs 纯 MCTS(1000) | 10/10、10/10 全胜 |
| AlphaZero vs 纯 MCTS(4000) | 10/10、10/10 全胜 |
| AlphaZero vs 纯 MCTS(8000) | 10/10、10/10 全胜 |

模拟次数增加 8 倍，结果毫无变化。原因在**随机走子本身**：9×9 上随机对局几乎不可能走出五连，搜索得到的状态价值近似等于噪声，增加模拟次数只是延长同一噪声的计算。因此：

1. 在本项目中，提高该基准的模拟次数并不能得到更强的对手（见上表）；
2. 该基准仅反映「有搜索 / 无搜索」的差异，不足以衡量模型的绝对强度；若需要有效的搜索基线，应把随机模拟换成轻量启发式走子，但每次模拟会显著变慢、次数只能降到数百，性价比不高；
3. 它从侧面支持了引入价值网络与策略网络的必要性：**只有树搜索、没有估值网络，在 9×9 上几乎不起作用**。

直接读取参考实现（junxiaosong/AlphaZero_Gomoku）的权重文件核对结构，并按棋格摊算：

| | 网络结构 | 参数量 | 棋格数 | **每格容量** |
| --- | --- | --- | --- | --- |

**6. 评估噪声**

- **实测**：同一检查点（累计 6650 局）、同样每色 10 局，执白 vs greedy 一次为 **0.50**、另一次为 **0.90**；20 局一次为 0.40。执黑也在 0.90 与 1.00 之间波动。
- **原因**：即使落子决策是确定性的（温度为 0、取访问次数最多的一手），GPU 浮点运算的非确定性仍会改变接近走法之间的选择，进而让整局棋走向完全不同，因此同一检查点的重复测量并不逐局一致。
- **方法学要求**：10–20 局、0.1 量级的差异不足以判定优劣；对照实验应提高局数（每色 30–40 局以上）或同一条件重复多次取平均；报告差异时**必须注明样本量**，并优先看方向是否在多次测量中一致。

| 6470 | 0.85 | 0.65 | 22.9 | 各 20 局 |
| 6480 | 0.95（和 0.05）| 0.55（和 0.05）| 12.9 | 各 20 局，已分胜 / 和 / 负 |
| 6650 | 0.90–1.00 | 0.40–0.90 | 17.6–22.8 | 20 局一次 + 10 局两次重复 |

> 6650 局的区间即「评估噪声」的直接体现：**同一份权重**下执白在 0.40 / 0.50 / 0.90 间波动，读表时应结合样本量理解，单次测量不代表精确水平。

**预期学习阶段**

```text
0 随机 → 1 聚集 → 2 防守 → 3 做活三/活四 → 4 双杀 → 5 战胜 greedy
```

**参考对照**：公开实现（8×8 五连）约需 2000–3000 局、800 次模拟/步达到可用水平。9×9 状态空间更大，预计需 **5000–10000 局**才能稳定具备「堵截与做威胁」能力。该数据取自公开实现，与本项目协议不同，仅作参考。

## 待办与下一步

按优先级排列：

1. **提高模拟次数**（训练与实战）。400 → 800 / 1600 有实验支持，是最直接的提升手段；代价是前端每步 1–2 秒变为 4–8 秒、训练慢 2–4 倍。建议先在前端试 800 次作为折中。
2. **中盘威胁剪枝**。不再用几何距离，而是用**棋理**筛选强制手：对手成活三 / 冲四时只保留「堵点 + 自己成四的点」。直击中盘（几何限制失效之处），不增加延迟，代价是实现快速行扫描。
3. **对手多样性**。历史对手池，或为 greedy 引入随机性（在分数接近的走法中随机选择）。针对自对弈退化的根因，属稳健性改进。
4. **扩大网络容量**。按每格容量摊算本项目偏薄（见「网络容量对比」），很可能是天花板之一。**建议用「部分权重迁移」暖启动而非从零训练**：形状匹配的部分（浅层卷积、两个全连接头）直接拷贝，新增通道随机初始化，优化器状态重置。
5. **提高评估局数**。每色 30–40 局以上，或同一条件重复多次取平均。**这是判断其它各项是否有效的前提**——当前噪声水平下，0.1 量级的改进难以分辨。
6. **以已知最好权重为准**（兜底）。6470 / 6480 附近的存档已是已验证的最好水平；若后续训练长期不能超过，直接采用该权重，把精力转向搜索与对手多样性。

**已排除的方向**

- **只搜索棋子附近的候选点**（几何邻近剪枝）。曾实现并测试后撤除：中盘棋子一多，半径 2 覆盖的候选即等于全盘（实测候选数 58 → 58，并未减少）；而在真正起作用的开局阶段，恰恰是「距现有棋子 3 格以上」的下法最合理的情形。该假设在实测中未获支持。
- **纯 MCTS 作为强度基准**。1000 / 4000 / 8000 次模拟对模型均 0/10 全败，增加次数无效，见「纯 MCTS 基准」。

## 训练与复现

- **棋盘** 9×9、五连；**训练环境** Python 3.11 + GPU（RTX 3060，torch 2.14.1+cu132）。
- **AlphaZero 训练**：项目根目录双击 [训练AlphaZero.bat](../训练AlphaZero.bat)，或执行 `py -3.11 -m rl.training.train_alphazero`（无限训练，Ctrl+C 停止后再次运行自动续训；每 10 局存盘并输出一行进度与自对弈健康指标，每 1000 累计局评估一次）。
- **AlphaZero 评估**：`py -3.11 -m rl.evaluation.eval_alphazero [games] [num_sims] [pure_playouts]`
  - `games`：每个颜色的对局数（默认 20）；
  - `num_sims`：模型每步模拟次数（默认 400）；
  - `pure_playouts`：大于 0 时加测纯 MCTS 基准（默认 0 即跳过）。
  - 固定温度为 0，但**结果不保证逐局可复现**，判读时务必结合样本量（见「评估噪声」）。
- **DQN 训练**：`py -3.11 -m rl.training.train_dqn`（同样支持无限训练与断点续训）。
- **Minimax 对照评估**：不训练、不加载 Minimax 权重。下列命令会让 Minimax 分别执黑、执白，与指定对手对局，并输出每色胜 / 和 / 负、每步平均搜索节点与决策耗时：
  ```bash
  # 各执黑、执白 10 局，对 Greedy
  uv run python -m rl.evaluation.eval_minimax greedy --games 10 --depth 2

  # 对 Random / 现有 AlphaZero（后者会加载 rl/models/alphazero.pt，需安装 torch）
  uv run python -m rl.evaluation.eval_minimax random --games 10 --depth 2
  uv run python -m rl.evaluation.eval_minimax alphazero --games 10 --depth 2
  # 可选：指定 AlphaZero 对手每步模拟数；默认沿用注册表的 400 次
  uv run python -m rl.evaluation.eval_minimax alphazero --games 10 --depth 2 --opponent-sims 200

  # 配置搜索：总半回合深度、普通候选上限、候选邻域半径；可关闭剪枝作对照
  uv run python -m rl.evaluation.eval_minimax greedy --games 2 --depth 3 --candidate-limit 6 --neighborhood 2
  uv run python -m rl.evaluation.eval_minimax greedy --games 2 --depth 2 --no-alpha-beta

  # 单元测试：接口/合法动作、一步成五、必堵、剪枝与未剪枝搜索结果一致
  uv run python -m unittest tests.test_minimax_agent -v
  ```
  `--games` 是**每种棋色**的局数，结果仅代表所运行的样本。对照实验应固定棋盘和规则、相同搜索配置，并同时报告黑白棋结果及对局数量；脚本输出的搜索节点与时间是 Minimax 自身的决策平均值。
- **网页切换**：Agent 注册名为 `minimax`。启动后端前可设置 `GOMOKU_AI=minimax`；搜索深度和普通候选上限可分别用 `GOMOKU_MINIMAX_DEPTH`、`GOMOKU_MINIMAX_CANDIDATES` 配置（默认 `2` / `8`）。例如 macOS/Linux 在项目根目录执行 `GOMOKU_AI=minimax GOMOKU_MINIMAX_DEPTH=2 make backend`，前端另用 `make frontend` 启动。也可以在网页 Agent 下拉框中切换。
- **新增文件**：`agents/minimax_agent.py` 为独立搜索 Agent；`evaluation/eval_minimax.py` 负责按颜色评估与统计搜索成本；`tests/test_minimax_agent.py` 覆盖搜索关键行为。实现复用 `BaseAgent` 接口、Environment 的状态/落子规则，以及 `q_learning._features` 和 Greedy 权重，不改现有训练过程与模型文件。
- **模型产物**：`models/alphazero.pt`（当前检查点，存 EMA 权重）、`models/alphazero_best.pt`（历史最佳，只在对 greedy 胜率创新高时更新）、`models/alphazero_meta.json`（累计局数与历史最佳成绩）、`models/dqn.pt` 与 `models/dqn_meta.json`、`models/q_learning.json`；`models/old_alphazero.*`（累计 17700 局）为改进前的历史版本，仅作留档。
