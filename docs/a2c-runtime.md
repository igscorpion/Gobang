## 实测时间与早期估算

完整主组为 90,000 局训练、14,400 局验证、1,200 局原始冻结测试。各计时字段累计如下（秒）：

| 训练种子 | 训练 | 验证 | 原始冻结测试 | 活动墙钟 |
|---|---:|---:|---:|---:|
| 11 | 653.5813 | 102.0691 | 8.4102 | 811.3672 |
| 22 | 567.5381 | 91.4491 | 8.6648 | 714.3314 |
| 33 | 570.1445 | 85.0855 | 8.2899 | 703.5031 |
| 合计 | 1,791.2639 | 278.6036 | 25.3648 | 2,229.2017 |

三个种子的活动墙钟累计约 **37.15 分钟**；字段含初始化、保存和调度等开销，因此不等于训练、验证、测试三列之和。这是恢复后保留的累计活动记录，排除中断停机，不是首次启动至完成的连续总用时。seed22 首次 CUDA 失败后从第 0 局完整检查点恢复，预算未减少；seed11 JSON 恢复审计额外重做的 400 局不计入原始测试量及上述测试计时，见 [恢复审计](../runs/production/a2c4_seed11/artifact_recovery.json)。

启动前曾估计每种子 20–60 分钟、三个种子约 1–3 小时；seed11 首 9,000 局活动墙钟约 214 秒（训练约 175 秒、验证约 26 秒）后，将规划更新为 45–90 分钟。现在应以完整记录为准，早期测量快照保存在 `experiments/a2c_control.json` 的 `runtime_estimate.first_formal_run_observation`。这里没有 AlphaZero 的每步 400 次 MCTS 搜索，因此不应按照 AlphaZero 的训练速度估算。

已有 DQN4 seed11 的 30,000 局日志累计约 27.6 分钟，平均每局约 31.49 个学习转移、37.16 次原始落子。它提供当前工程的实际速度参考，不能直接当作 A2C 耗时。A2C 的策略、局长、同步批量利用率和更新频率都会不同。

估时分解为：`训练局数 × [每局学习转移数 × (batch8采样时间/8 + update40时间/40 + 编码及环境开销) + 对手开销] + 验证/测试 + 保存及调度开销`。小批量同步、屏障尾批次、历史对手推理与 CPU/Python 调度使简单算术外推偏乐观，规划区间留有余量。

## 本机测量

测量使用 PyTorch 单 CPU 线程；CUDA 项在计时边界同步。每种网络预热后测 30 次采样/单局面推理、20 次梯度更新，表中为中位数。batch8 采样包含合法动作屏蔽、概率采样及动作取回 CPU；update40 包含策略/价值/熵损失、反向传播、梯度裁剪及 Adam。

| 候选网络 | 参数量 | CUDA batch8采样 | CUDA update40 | CPU update40 |
|---|---:|---:|---:|---:|
| 32/64/64 + FC256，原方案 | 1,405,042 | 1.03 ms | 4.28 ms | 22.97 ms |
| 32/64/64 + FC64 | 393,778 | 1.05 ms | 3.55 ms | 14.09 ms |
| 16/32/32 + FC64 | 185,762 | 1.01 ms | 3.76 ms | 6.04 ms |

Greedy 单次选点中位约 0.45 ms，八个状态编码约 0.48 ms，十次环境落子约 0.28 ms。它们会随局面、缓存和运行负载变化，不能当作全程恒定值。单局面推理在这些小网络上 CPU 可能更快；最终实现可分别测评估设备，再固定所有种子的协议。

## 网络选择

**本轮已保留原方案并完成主对照。** 140.5 万参数的 FP32 权重约 5.36 MiB（不含优化器、梯度与激活），对本机显卡不算大，并且与 DQN4 的容量几乎一致，符合此前优先效果和可比性的要求。近似同容量与同课程机制不代表严格等计算预算；实际冻结测试显示 A2C 对 Greedy 仍弱。

FC256→FC64 可减少约 72% 的参数，但本次 CUDA 更新只快约 17%，采样速度接近；整个实验不会按参数缩小比例加速。更小的 16/32/32 网络在本次 GPU 测量中没有进一步的更新速度优势，不能根据参数量推断它更快或棋力足够。

已把 393,778 参数的 FC64 版本保存为可选轻量配置。如果采用它替代主组，须将对照描述改为“轻量 A2C 与现有 DQN4 的实用比较”；若要继续作近似等容量比较，需另补相同小骨干的 DQN 参照。当前没有自动追加轻量组训练，也没有改变 90,000 局预算。轻量网络的棋力需要真实验证后判断。
