## 算法与固定初始参数

采用 **同步 n-step A2C**：8 个环境，每个环境采集最多 5 个学习转移，合并最多 40 条样本更新一次。每轮采样期间冻结学习网络，统一更新后才采集下一轮；可以在一个进程内批量推理，不要求引入额外并行框架。

网络复用 DQN4 的三层卷积和 FC256，增加独立的策略线性头与价值线性头。策略只对合法动作归一化；训练按概率采样，验证和测试取合法动作中的最大概率。价值头输出当前行动方的价值。新增的价值头有 257 个参数，容量差异约 0.018%。

固定参数如下；本轮保持预先指定的设置，未根据最终测试调参。

| 参数 | 设定 |
|---|---:|
| Adam 学习率 | 0.0003 |
| 每个学习转移的 gamma | 0.99 |
| n-step | 5 |
| 同步环境数 | 8 |
| 价值 MSE 系数 | 0.5 |
| 熵奖励系数 | 0.01 |
| 梯度范数上限 | 5 |
| 每轮轨迹更新次数 | 1 |

损失为 `-mean(log π(a|s) × stop_gradient(G−V(s))) + 0.5×MSE(V(s), stop_gradient(G)) − 0.01×mean(entropy)`。主方案使用原始优势，不做优势标准化；每轮新鲜轨迹更新后释放，不混入历史经验回放。

### 零和视角与折扣

四通道严格调用 `state_to_tensor4`，其棋盘始终相对当前行动方。n-step 回报按 `G_t = r_t + gamma × sign_t × (1−done_t) × G_(t+1)` 反向递推；非终局截断处以冻结的下一状态价值 bootstrap，终局 bootstrap 为零。

- 自对弈一手后切换到对手视角，`sign=-1`；奖励相对刚落子方，获胜落子为 +1，其他为 0。败方通过负号获得相反的未来价值，不能把下一方的正价值直接相加。
- 对 Greedy、Random 或历史对手时，合并“学习者落子 + 对手回应”，回到学习者视角，`sign=+1`；终局奖励按学习者颜色取胜 +1、负 −1、和 0。对手动作不进入学习者的策略梯度样本。
- 为对齐现有 DQN，gamma 按一个学习转移计算：自对弈一手与外部对手两手转移各折扣一次。这不是逐原始落子的统一折扣；两种转移的原始落子数需分别记录。
- 跨环境、跨新棋局的回报不得串联；终局、填充位置和无合法动作状态都必须正确屏蔽。

## 训练对手与可比性

沿用 DQN 的机制：Greedy 比例从 0.1 开始，用 `curriculum_ratio` 根据验证结果调整；Random 固定 0.15；历史池可用后占 0.15；其余为自对弈。历史模型每 1,000 局保存一份，最多四份，每局选定后冻结；历史 A2C 对手采用合法最大概率动作并以 0.05 概率随机探索，以对齐历史 DQN 对手的探索口径。

外部对手对局根据全局分配的 episode ID 交替先后手。自对弈双方均使用本轮冻结的学习策略。各类对手的实际对局数、颜色和课程比例均写入日志。

**这里控制的是相同课程机制。** 不同算法的验证表现会导致实际 Greedy 比例不同，历史池也由各自策略产生；同步批量与单局更新亦存在区别。因此主结论是完整学习方法的比较，不能把差异全部归因于 A2C/DQN 的更新公式。若要进一步隔离这一点，需另立 A2C 与 DQN 都使用固定 Greedy 0.6 / Random 0.4、统一对手种子的配对重训实验；该扩展不计入当前 90,000 局预算。

## 验证、冻结测试与统计

与 DQN 保持一致：每完成 1,000 局，在 Random、Greedy 上分别执黑和执白各验证 40 局；每个种子共 30 次验证。验证黑方种子从 300000 开始，白方从 400000 开始。可选的第 0 局检查仅作未训练参考，不参与本组模型选择。

`best.pt` 只按验证集 Greedy 的黑白平均 `score=胜率+0.5×和率` 选择；平分保留较早模型。训练完成后冻结它，对 Random、Greedy 分黑白各测试 100 局，使用独立的 800000/900000 种子。三个训练种子的验证合计 14,400 局，最终测试合计 1,200 局，均不计入 90,000 局训练预算。

验证和测试暂停学习、固定推理策略，并恢复训练的 RNG 与模型模式。测试结果不反馈课程、不挑选种子或超参。看到测试结果后再更改超参，应另建实验目录并重新声明验证和测试协议。

结果按以下口径记录；未完成的 DQN4 种子不填入最终成绩：

| 比较项 | 报告方式 |
|---|---|
| 每种子 × 对手 × 颜色 | 胜/和/负、胜率、和棋率、score、胜率的 95% Wilson 区间 |
| 三种子重复 | 胜率和 score 的均值、样本标准差，保留三个原始值 |
| A2C 减 DQN4 | 相同训练种子下的分色胜率差与 score 差，再汇总配对差 |
| 学习效率 | 在 1k/5k/10k/20k/30k 局处的验证值，以及按真实落子数和训练耗时的曲线数据 |
| 成本 | 原始落子数、学习转移数、梯度更新数、实际 rollout 样本数、参数量、训练/验证/测试耗时、推理延迟 |

相同局数不代表相同样本数、更新次数或计算成本。Wilson 区间描述一次冻结策略的对局胜率，不替代训练种子间不确定性；三个种子也不足以自动保证统计显著性。

## 检查点与实施验收

为使多环境训练能够精确续训，按 250 局划分分配屏障：不给环境分配超过当前边界的新局，待在途棋局全部结束，完成最后一个可能不足 40 条的 rollout 更新后再保存。这样检查点中没有半局状态；下一屏障继续分配到最终精确 30,000 局。1,000 局边界处先保存历史快照、再验证并更新课程，随后保存检查点，与 DQN 的顺序保持一致。

检查点须包含网络、Adam、完成与待分配 episode ID、计数器、课程比例、历史策略、最佳验证分数、Python/NumPy/Torch/CUDA 与各环境 RNG、完整参数配置。中断时从上一完整屏障恢复，回退其后的未持久化日志；输出目录和锁按种子隔离。

以下实现验收已通过核心测试、精确续训测试与 CPU/CUDA 冒烟验证：

1. 对立即获胜、下一手败北、和棋、非终局截断、固定对手两手转移构造可手算的 n-step 目标，检查正负号、done 与折扣。
2. 检查合法动作屏蔽、熵与梯度的有限性、策略采样与确定性评估切换，以及跨棋局回报隔离。
3. 用缩小环境数和训练量验证连续训练与屏障恢复的参数、RNG、累计计数和日志一致。
4. 短程冒烟运行完整走通验证选择、冻结测试、best/final 分离和报告；三种子阶段已接入独立 A2C 队列。

产物为各 `a2c4_seed*` 目录中的 config、training/updates/validation CSV、current/best/final 权重、latest.checkpoint、最终逐局记录与评估 JSON，以及单独的 A2C–DQN 对照报告。三个种子的最终测试均已核验；候选通过独立的 `a2c_models.json` 按验证结果注册到网页，避免原调度器覆盖 A2C 注册信息。
